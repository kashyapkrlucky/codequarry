## Document skeleton

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Page title · Site</title>
    <meta name="description" content="One-sentence summary for search results." />
    <link rel="canonical" href="https://example.com/page" />
    <link rel="icon" href="/favicon.svg" type="image/svg+xml" />
    <meta property="og:title" content="Page title" />
    <meta property="og:image" content="https://example.com/og.png" />
    <link rel="stylesheet" href="/styles.css" />
    <script src="/app.js" type="module"></script>
  </head>
  <body>…</body>
</html>
```

<Callout type="tip">
Module scripts are deferred by default. For classic scripts use `defer` (runs in order after parsing) or `async` (runs as soon as loaded, any order).
</Callout>

## Semantic layout

```html
<header>
  <nav aria-label="Main">…</nav>
</header>
<main id="main">
  <article>
    <h1>Title</h1>
    <section aria-labelledby="install">
      <h2 id="install">Install</h2>
    </section>
  </article>
  <aside>Related links</aside>
</main>
<footer>…</footer>
```

| Element | Meaning |
| --- | --- |
| `main` | The page's primary content (one per page) |
| `article` | Self-contained content that makes sense on its own |
| `section` | Thematic grouping, usually with a heading |
| `nav` | A major block of navigation links |
| `aside` | Tangential content (sidebars, callouts) |
| `figure` / `figcaption` | Media with a caption |
| `time` | Machine-readable date: `datetime="2026-11-08"` |

Use one `h1` per page and don't skip heading levels — screen-reader users navigate by headings.

## Text-level elements

| Element | Use for |
| --- | --- |
| `strong` / `em` | Importance / stress emphasis (not just bold/italic) |
| `code`, `kbd`, `samp`, `var` | Code, keyboard input, program output, variables |
| `abbr title="…"` | Abbreviations |
| `mark` | Highlighted / matched text |
| `del` / `ins` | Removed / added content |

## Links and buttons

```html
<a href="/docs">Internal link</a>
<a href="https://example.com" target="_blank" rel="noopener noreferrer">External</a>
<a href="/report.pdf" download>Download PDF</a>
<button type="button">Open menu</button>
```

<Callout type="warning">
Links navigate; buttons perform actions. A clickable `div` is not focusable, has no role, and ignores Enter/Space — use a real `button`.
</Callout>

## Forms

```html
<form action="/subscribe" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email" required />

  <fieldset>
    <legend>Plan</legend>
    <label><input type="radio" name="plan" value="free" checked /> Free</label>
    <label><input type="radio" name="plan" value="pro" /> Pro</label>
  </fieldset>

  <label for="role">Role</label>
  <select id="role" name="role">
    <option value="dev">Developer</option>
    <option value="mgr">Manager</option>
  </select>

  <button type="submit">Subscribe</button>
</form>
```

| Attribute | Effect |
| --- | --- |
| `required`, `minlength`, `maxlength`, `min`, `max`, `pattern` | Built-in validation |
| `type="email" / "url" / "number" / "date" / "search"` | Validation + mobile keyboards |
| `autocomplete="email" / "current-password" / "one-time-code"` | Autofill hints |
| `inputmode="numeric"` | Numeric keyboard without number-input quirks |
| `aria-describedby="hint-id"` | Associates help or error text |

Client-side validation is a convenience — always validate again on the server.

## Media

```html
<img src="/hero.webp" alt="Dashboard showing weekly signups" width="1200" height="630"
     loading="lazy" decoding="async" />

<picture>
  <source srcset="/hero.avif" type="image/avif" />
  <img src="/hero.jpg" alt="…" width="1200" height="630" />
</picture>

<video controls preload="metadata" poster="/poster.jpg">
  <source src="/demo.mp4" type="video/mp4" />
  <track kind="captions" src="/demo.vtt" srclang="en" label="English" />
</video>
```

Always set `width` and `height` to prevent layout shift. Decorative images get `alt=""`.

## Tables

```html
<table>
  <caption>Plan comparison</caption>
  <thead>
    <tr><th scope="col">Feature</th><th scope="col">Free</th><th scope="col">Pro</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Projects</th><td>3</td><td>Unlimited</td></tr>
  </tbody>
</table>
```

## Built-in interactive elements

```html
<details>
  <summary>Show advanced options</summary>
  <p>Collapsible without JavaScript.</p>
</details>

<dialog id="confirm">
  <form method="dialog">
    <p>Delete this item?</p>
    <button value="cancel">Cancel</button>
    <button value="ok">Delete</button>
  </form>
</dialog>
<!-- document.getElementById("confirm").showModal() -->

<button popovertarget="menu">Menu</button>
<div id="menu" popover>Popover content</div>
```

## Common mistakes

- **Missing `lang`** on `html` — breaks pronunciation for screen readers and translation tools.
- **Placeholder as label** — placeholders disappear and have low contrast; always use a `label`.
- **Images without dimensions** — causes cumulative layout shift.
- **Headings chosen for size** instead of hierarchy — style with CSS instead.
